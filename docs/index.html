Know what else has to change.

You edit a file and miss the one that always moves with it. Review catches it, or production does. Git Synapse reads the history you already have and answers the question before you open the pull request.

How it works

There is no language parser and no model of your framework. The base fact is simply this commit touched this file, and everything is built from that.

🧩

It reads real commits

Files that repeatedly changed together, drawn from your own history. Works on any language, because it never looks inside the file.

⚖️

It shows its evidence

Every suggestion carries how often the pair actually moved together, so you can tell a real coupling from two files that are merely busy.

🔗

It crosses repositories

Where one repository declares another as a dependency, it tracks how quickly version bumps are adopted downstream.

Three ways to ask

The same corpus behind a dashboard, an HTTP API, and a tool an agent can call directly.

Dashboard

Browse repositories, open a file, and read its strongest couplings with the evidence beside them.

http://localhost:8080

MCP server

Fourteen tools, so a coding agent can ask what moves together before it writes the patch.

http://localhost:8081/mcp

HTTP API

The same answers as JSON, for scripts, checks in CI, and anything else you want to build on it.

GET /api/files/{id}/coupled

Start here

Docker brings up the API, dashboard, Postgres, scheduler and MCP server together. You do not need Python, Git or a database on the host.

$ git clone https://github.com/kirankn8/git-synapse.git $ cd git-synapse $ cp .env.example .env $ docker compose up -d
Full setup guide →
🔐 It opens with no sign-in, so you can try it in a couple of minutes. Put ADMIN_EMAIL and ADMIN_PASSWORD in .env and restart before you put it anywhere other people can reach.
